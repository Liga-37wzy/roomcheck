# 实现与维护

Python 3.11+ 标准库。无需安装依赖；以 `python -m roomcheck` 运行源码包。CLI 负责读文件、稳定 UTF-8 输出和退出码；`core.py` 不读文件、不写文件、不使用网络，便于后续接表单或 API。

## 算法

1. 严格验证输入并转为不可变 dataclass / frozenset。
2. 广度优先搜索 `(inventory, completed_actions)`；同状态合并，保留一条最短父路径。
3. 存储反向边，从所有胜利状态反向搜索，标记仍可获胜的状态。
4. 若完整搜索存在胜利，但某个可达状态不在标记集合中，返回软锁反例。
5. 比较胜利状态已做动作与 `must_solve`；检查未执行过的动作。

必须把 completed_actions 放进状态键：相同库存可能有不同的“还剩哪些一次性操作”，不能只按库存合并。所有动作一次性使状态深度最多等于动作数，因此无需处理无限循环游戏。依赖图可以有环，状态转移图中的完成集合仍单调增长。

搜索耗时约 O(S × A × F + E)，内存约 O(S × (F + A) + E)，S 为状态数、A 为动作数、F 为事实数、E 为转移数。状态数可指数增长；40 个互相独立的动作也很可能超过预算。默认 20,000 状态不是“支持所有 40 步密室”的承诺。

## 改代码从哪里入手

先读并修改 `examples/softlock.json`，理解消耗语义；再看 `check()` 中的动作可执行条件。新增规则时先定义输入、状态变化和至少一对正常/异常行为案例。不要只测试某段函数是否被调用。

测试包括可重复使用线索、一次性物品、AND+OR、绕过、初始胜利、终止语义、恢复路径、带初始入口的环、输入与状态预算，以及 100 个固定随机种子的四动作模型。随机案例与独立递归枚举动作序列比较通关性、全状态可恢复性和绕过结论，以降低同一算法自证正确的风险。

测试不连接互联网，也不批量删除文件。Python 可能创建 `__pycache__`，已被 `.gitignore` 排除。若以后支持可重复动作，当前递归对照与深度终止假设都必须修改。

## 发布与数据边界

模型文件是数据，不执行其中代码；读取上限 1 MiB，拒绝重复键和未知字段。当前不是多租户服务，没有上传 API。模型本身包含谜题剧透，应由设计者决定哪些可以公开；项目仅附原创演示模型。
