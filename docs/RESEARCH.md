# 公开资料调研与证据分级

调研日期：2026-11-20。方法：浏览公开仓库 README、工具作者产品页和设计者讨论。未安装或运行竞品，没有访谈真实用户，没有验证付费意愿。本项目作者当前没有自己的密室流程或设计者资源。

## 已核实的工具

| 工具与一手来源 | 来源明确展示的能力 | 对本项目的影响 |
|---|---|---|
| [DepDoodle](https://github.com/Fulviuus/depdoodle) | 桌面依赖图编辑、AND/OR、结构检查、试玩模拟、节奏视图 | 不能宣称依赖检查或模拟是独有功能；更适合需要图形编辑的用户 |
| [Puzzle Dependency Chart Studio](https://wishiwasalemon.itch.io/puzzle-dependency-chart-20studio) | 浏览器画布、谜题/物品/目标节点、JSON 保存加载 | 不能把无需账户或 JSON 当独有壁垒 |
| [Puzzle Dependency Grapher](https://mattj375.itch.io/puzzle-dependency-grapher) | 简单文本语法、循环依赖检查、玩家进度标记 | 单纯循环检测不足以构成差异 |
| [GraphEG](https://github.com/martin-verjans/GraphEG) | 静态场景设计和游戏动作模拟；README 列出 Visual Studio、GraphViz、Git 安装要求 | 图模型与状态模拟已有相关研究；本项目可探索更轻量的 CLI 入口 |

对来源没有提及的功能，结论是“未确认”，不是“不支持”。尚未做竞品相同输入的性能或准确率实测。

学术背景：[Yernaux、Verjans、Vanhoof 的论文](https://gonzagueyernaux.com/papers/gala2025.pdf)讨论用图表示场景与游戏推进，并以 GraphEG 为配套工具。它支持把逻辑可达性作为技术方向，但不证明本项目的市场需求。RoomCheck 是独立的小型状态搜索实现，不是该论文模型的完整实现或复现。

相关游戏实现：[LAShemilt/adventure-time](https://github.com/LAShemilt/adventure-time)包含文字密室的 Room、Items、Locks 和调试流程，说明线上解谜也存在明确的状态与解锁条件。它是游戏项目，不能据此推断其作者需要独立检查器。

## 需求证据

[Puzzle Planning Tools 讨论](https://www.reddit.com/r/escaperooms/comments/1hh4go6/puzzle_planning_tools/)中，发帖者询问如何组织非线性谜题推进；回复提到流程图、draw.io、Miro、Obsidian 和表格。这是实际工作方法的定性线索，样本自选且数量少。它支持“有人需要管理依赖关系”，不支持“大家需要付费的自动检查器”。

Studio 作者页面还存在用户针对移动端、保存和画布的反馈，说明工具可用性本身有需求；与自动找软锁的需求不能混为一谈。

| 判断 | 证据等级 | 当前结论 |
|---|---|---|
| 已有专门谜题依赖工具 | 产品/项目一手文档 | 已确认存在 |
| 部分设计者用图组织非线性流程 | 自发讨论 | 有定性支持，不能外推规模 |
| 消耗道具会产生顺序相关问题 | 形式模型及可复现合成案例 | 技术上可验证；真实发生频率未知 |
| 用户愿意手写 JSON | 无用户测试 | 未验证，可能成为最大阻力 |
| 反例报告比现有工具节省时间 | 无对照试验 | 未验证 |
| 实体与线上用户愿意共用该工具 | 用户希望覆盖两者 | 产品范围选择，不是市场证据 |
| 用户愿意付费、能形成社区 | 无证据 | 不作承诺 |

## 候选差异与替代方案

RoomCheck 提供版本化的输入、道具消耗语义、可重放的失败路径和明确的搜索边界。可能的长期价值来自高质量真实回归案例、与设计流程的兼容性和低录入成本；目前这些积累尚不存在。AI 可以未来辅助录入，但不能替代确定性检查，也不能算现有竞争优势。

如果用户只需画图，应优先考虑已有编辑器。如果用户不愿意维护单独模型，应先研究从现有数据导入，而不是继续添加检查规则。对于复杂多人和可重复机关，专门游戏引擎或更通用的模型检查工具可能更合适。
